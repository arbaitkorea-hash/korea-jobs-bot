# SEO — JST ART

Что уже реализовано технически, семантическое ядро под RU/EN/KO и пулы хэштегов.

## 1. Что реализовано в коде

| Требование | Где реализовано |
|---|---|
| Отдельные URL на язык (`/ru`, `/en`, `/ko`) | `src/app/(public)/[lang]/`, редирект и определение языка — `src/proxy.ts` |
| Свой slug на каждом языке | Таблицы `*Translation`, поле `slug`, уникальность по `(locale, slug)` |
| `hreflang` + `x-default` на каждой странице | `src/lib/seo.ts` → `buildAlternates()`, вызывается в `generateMetadata` каждой страницы |
| Уникальные title/description на язык | Поля `seoTitle`/`seoDescription` в переводах, задаются в админке отдельно |
| `sitemap.xml` с языковыми альтернативами | `src/app/sitemap.ts` — каждая запись содержит `alternates.languages` |
| `robots.txt` | `src/app/robots.ts` |
| JSON-LD: VisualArtwork, Product, Person, Organization, BreadcrumbList, WebSite+SearchAction, Article | `src/lib/jsonld.ts` |
| Мета-теги под Naver | `src/app/(public)/[lang]/layout.tsx` (`naver-site-verification`, `author`, `subject`) |
| SSG/ISR всех публичных страниц | `export const revalidate = 3600` + `generateStaticParams` |
| Alt обязателен на 3 языках | Блокировка публикации в `saveArtwork` (`actions.ts`) |
| Чистые ЧПУ-URL | Валидация slug: `^[a-z0-9-]+$` в `src/lib/validation.ts` |
| Внутренняя перелинковка | Блок «из той же коллекции» на карточке работы, хлебные крошки |
| `next/image` + `next/font` | Во всех компонентах; шрифты самохостятся при сборке |
| Авто-обложки для соцсетей (OG) | `src/lib/og.tsx` + `opengraph-image.tsx` в трёх местах: раздел языка, карточка работы, статья блога |
| Разметка выставок (`ExhibitionEvent`) | `src/app/(public)/[lang]/exhibitions/page.tsx` |
| Фильтр по цвету как индексируемый URL | `?color=` в `gallery/page.tsx`, значения из белого списка |
| Формула SEO-текстов работы | `src/lib/seo-copy.ts`; кнопка «Собрать по работе» в админке, тот же генератор в импорте и массовой загрузке |
| Цена в валюте посетителя | `src/lib/currency.ts` + компонент `Price`; в JSON-LD остаётся исходная валюта работы |

### Про Naver

Naver ранжирует иначе, чем Google, и это учтено:

- **Верификация**: тег `naver-site-verification` выводится только если задан
  `NEXT_PUBLIC_NAVER_VERIFICATION` (пустой `content` Naver считает невалидным).
  Код берётся в [Naver Search Advisor](https://searchadvisor.naver.com).
- **Мета `author` и `subject`**: Naver исторически читает их, Google — нет.
- **robots.txt**: бот Naver (`Yeti`) читает общую секцию `User-agent: *`,
  отдельная секция не требуется.
- **Регистрация сайта**: sitemap нужно подать в Search Advisor вручную —
  автоматически Naver его не находит, в отличие от Google.
- **Корейский текст должен быть настоящим переводом.** Naver сильно понижает
  машинный перевод. Тексты в `ko.json` и в сиде написаны как самостоятельный
  корейский, а не подстрочник с русского.

### Про авто-обложки

У каждой работы и статьи своя карточка 1200×630, которая рисуется на лету:
слева картина, справа название, техника, размер и цена. Задавать картинку
руками не нужно — но если в админке заполнено поле «OG-изображение», побеждает
оно. Разделы без своей карточки (о художнике, выставки, доставка, контакты)
наследуют языковую обложку раздела, поэтому ссылка на любую страницу в
мессенджере выглядит оформленной, а не голым URL.

Шрифт для карточки скачивается подмножеством под конкретный текст — поэтому
корейский заголовок рисуется хангылем, а не квадратами, и при этом не тянет
за собой шеститмегабайтный файл.

## Формула описаний: как работа попадает в выдачу

Запрос, по которому покупают живопись, во всех трёх странах устроен одинаково:
**сюжет + техника + размер + слово намерения**. «Купить картину маслом 70х50»,
«acrylic seascape for sale», «유화 원화 판매». Поэтому заголовок собирается по
формуле, а не «как напишется»:

```
{Название} — купить {картину акрилом} {70×50} см | JST ART
{Title} — original {acrylic painting} for sale, {70×50} cm | JST ART
{제목} — {아크릴화} 원화 {70×50}cm 판매 | JST ART
```

Описание для выдачи — три части в жёстком порядке:

1. **Зацепка.** Первая фраза авторского описания: «Пасмурный день, когда у моря
   нет ни одного яркого цвета». Именно она решает, кликнут по сниппету или
   пролистают — не ключевые слова.
2. **Факты и уникальность.** «Оригинал 70×50 см, холст, акрил — единственный
   экземпляр». Единственность — главный аргумент оригинала против принта.
3. **Призыв и снятие возражения.** «Купить с доставкой из Кореи по всему миру».
   Доставка закрывает вопрос «это же в другой стране», который иначе останется
   без ответа.

Всё вместе укладывается в 160 символов — предел, после которого Google обрезает
описание. Зацепка обрезается по границе слова, а не на середине.

У проданной работы призыв меняется на честный: «Работа продана — напишите,
если нужна похожая». Обещать покупку того, чего нет, нельзя — это разочарование
на входе и отказ, который поисковик считывает как плохой ответ на запрос.

Формула живёт в одном месте — `src/lib/seo-copy.ts` — и применяется одинаково
из кнопки «Собрать по работе», из импорта каталога и из массовой загрузки.
Когда формула меняется, `npm run db:import -- --refresh-seo` пересобирает
заголовки у всех работ, не трогая авторские тексты.

### Про Naver

Naver ранжирует иначе Google: он сильнее опирается на собственные площадки и
на свежесть. Формула помогает, но недостаточна — после запуска нужно
зарегистрировать сайт в Naver Search Advisor и вести корейский блог: у Naver
это основной канал попадания в выдачу для внешнего сайта.

### Как этим пользоваться

1. Один запрос — одна страница. Не пытайтесь ранжировать галерею и карточку по одному запросу.
2. Ключ должен попасть в: `seoTitle`, первые 120 символов `seoDescription`, `altText`, `slug` и в текст описания работы.
3. Начинайте с низкочастотных: по ним карточка конкретной работы может выйти в топ за недели, а не за годы.
4. Не переспамьте: 1–2 вхождения на текст. Naver за переспам понижает жёстче Google.

## 4. Что нужно сделать руками после деплоя

1. **Google Search Console** — подтвердить домен, подать `sitemap.xml`.
2. **Naver Search Advisor** — зарегистрировать сайт, получить код верификации,
   положить его в `NEXT_PUBLIC_NAVER_VERIFICATION`, подать sitemap вручную.
3. **Bing Webmaster Tools** — можно импортировать настройки прямо из Search Console.
4. Заполнить SEO-поля у каждой работы **на всех трёх языках** (в админке
   на вкладке каждого языка горит индикатор заполненности).
5. Заменить демо-изображения настоящими фотографиями работ — Google
   учитывает и качество, и размер изображений на странице товара.

## 5. Ограничения текущей реализации

- **Фильтр по цвету** есть в схеме (`dominantColor`) и заполняется в админке,
  но в UI галереи не выведен — цветовой пикер требует продуманного UX,
  которого спецификация не описывает.
- **Поиск** работает по названию, описанию, истории и ключевым словам текущего
  языка (`/gallery?q=…`, тот же адрес заявлен в `SearchAction`). Это `LIKE`-поиск
  по подстроке, без учёта морфологии: «пейзажи» не найдёт «пейзаж». Для
  небольшого каталога этого достаточно; при росте — полнотекстовый индекс
  PostgreSQL (`tsvector`) без изменения интерфейса `getGalleryArtworks`.
- Блог создан, но наполнение (главный источник информационного трафика) —
  за владельцем.
