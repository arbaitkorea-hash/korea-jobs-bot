## Стек и главные ловушки

| | |
|---|---|
| Next.js | **16.3.0**, App Router, Turbopack |
| React | 19.2 |
| TypeScript | 5 |
| Tailwind | **v4** (CSS-first, `@theme` в `globals.css`, конфиг-файла нет) |
| БД | PostgreSQL + **Prisma 6.19** |
| Авторизация | NextAuth v5 beta (credentials + bcrypt) |
| Картинки | sharp |
| Валидация | Zod 4 |

**Ловушки, на которых легко ошибиться — они отличаются от того, что ты «помнишь»:**

1. **Это не тот Next.js, который ты знаешь.** Версия 16 содержит ломающие
   изменения. Перед тем как писать код, читай документацию прямо в проекте:
   `node_modules/next/dist/docs/`. Это требование зафиксировано в `AGENTS.md`.
2. **`middleware.ts` больше нет — файл называется `src/proxy.ts`.** В Next 16
   он выполняется в Node.js-рантайме (проверено в
   `node_modules/next/dist/build/utils.js`, функция `isProxyFile()`), поэтому
   там работают NextAuth и Prisma.
3. **Prisma намеренно 6, а не 7.** Седьмая требует driver adapters и убирает
   `url = env("DATABASE_URL")` из схемы. Не обновляй.
4. **`params` и `searchParams` — промисы.** Их нужно `await`. Это касается и
   метаданных, и `opengraph-image.tsx`.
5. **Два корневых layout через route groups** — `(public)` и `(admin)`. Файла
   `src/app/layout.tsx` нет и быть не должно.
6. Tailwind v4: цвета и размеры объявляются в `@theme` внутри
   `src/app/globals.css`, отдельного `tailwind.config` нет.

## Архитектура

### Языки — три равноправные версии, а не переключатель текста

`/ru`, `/en`, `/ko` — отдельные URL. Реализовано нативно: сегмент `[lang]` +
загрузчик словарей (`src/lib/i18n/`), без `next-intl`.

**У каждой работы свой slug на каждом языке.** «Перед грозой» →
`/ru/gallery/pered-grozoy`, `/en/gallery/before-the-storm`,
`/ko/gallery/pokpung-jeon`. Переключатель языка находит реальный адрес перевода,
а не кидает на главную. Уникальность гарантируется индексом
`@@unique([locale, slug])`.

`src/lib/slugify.ts` — своя таблица транслитерации (русский + романизация
хангыля по пересмотренной системе). **Не заменяй на библиотеку:** slug — это
навсегда зафиксированный URL, поведение не должно поехать при обновлении
зависимости. В файле есть проверка длины таблиц — она стоит там после реального
бага, когда «폭풍» превращалось в «pokput» вместо «pokpung».

### Данные

Все переводимые тексты вынесены в таблицы `*Translation`
(`ArtworkTranslation`, `CollectionTranslation`, `BlogPostTranslation`,
`ExhibitionTranslation`). Основные модели: `Artwork`, `ArtworkImage`,
`Collection`, `Exhibition`, `BlogPost`, `Order`, `OrderItem`, `ContactMessage`,
`AdminUser`, `AuditLog`, `ExchangeRate`, `SiteKeywords`.

Три миграции: `init_multilingual`, `exhibitions_and_color_family`,
`exchange_rates`.

### Рендеринг

SSG/ISR: `generateStaticParams` + `export const revalidate = 3600` на всех
публичных страницах. Это условие попадания в выдачу Naver, чей краулер плохо
переваривает страницы, собирающиеся в браузере.

## Что уже сделано

### Публичная часть
- Главная — одна длинная страница: обложка → рассказ о живописи → избранные
  работы → оплата и доставка → форма связи
- Галерея с фильтрами: коллекция, техника, **цвет**, ориентация, цена, поиск.
  Фильтры — обычная GET-форма без JS, результат можно переслать ссылкой
- Страница работы: вкладки «Фотография» / «На стене», зум, корзина, похожие
  работы. **Широкие холсты** (шире высоты в 1.15 раза) идут во всю ширину,
  текст уходит под них двумя колонками
- Коллекции, о художнике, блог, **выставки и пресса**, оплата и доставка,
  контакты, корзина, оформление заказа, политики
- Тёмная тема (переключатель + системная настройка)

### «На стене» — вместо 3D
`src/components/artwork/wall-preview.tsx`. Работа показывается в настоящем
масштабе: высота стены 280 см, рост фигуры 170 см, центр работы на 150 см от
пола (музейная норма). Три цвета стены. **3D-зал заказчик отверг осознанно** —
не предлагай его снова. Возможное развитие — AR через нативные просмотрщики
iOS/Android, но это отложено.

### Админка (`/admin`)
- Работы: CRUD с вкладками RU/EN/KO, SEO на каждый язык, drag-and-drop порядок,
  **звезда «на главную»** прямо в списке
- **Массовая загрузка** (`/admin/artworks/bulk`): перетащить до 60 фотографий,
  задать общие параметры на всю партию, построчно поправить. Загрузка идёт
  последовательно — параллельные конвертации sharp съедают память инстанса
- Коллекции, выставки, блог, ключевые слова, **курсы валют**, заказы,
  сообщения, аналитика
- Светофор заполненности SEO по каждому языку
- **Публикация заблокирована**, пока нет alt-текста на всех трёх языках и хотя
  бы одного изображения

### SEO
- hreflang + x-default на каждой странице и в sitemap
- JSON-LD: VisualArtwork, Product, Person, Organization, BreadcrumbList,
  WebSite+SearchAction, Article, ExhibitionEvent
- Мета-теги под Naver, поле для кода Search Advisor
- **Формула SEO-текстов** (`src/lib/seo-copy.ts`): заголовок собирается как
  «название + техника + размер + слово намерения» (купить / for sale / 판매),
  описание — «зацепка + факты с упором на единственность + призыв с ответом на
  возражение о доставке», ≤160 символов, обрезка по границе слова. У проданной
  работы призыв честный: «напишите, если нужна похожая». Один и тот же генератор
  работает из кнопки «Собрать по работе», из импорта каталога и из массовой
  загрузки
- Авто-обложки для соцсетей: карточки 1200×630 для работы, статьи и языкового
  раздела. Шрифт скачивается подмножеством под конкретный текст — иначе
  корейские заголовки либо рисуются квадратами, либо тянут 6 МБ

### Цены и валюта
Цена задаётся в одной валюте (сейчас рубли). Посетителю показывается в валюте
его страны: Корея — воны, Россия и соседи — рубли, остальные — доллары. Страну
даёт geo-заголовок хостинга, `src/proxy.ts` кладёт её в куку, подменяет цену
клиентский компонент `Price` — так страницы остаются статическими. Пересчёт
помечен «≈» и подписан исходной ценой. Курсы задаются руками в `/admin/rates`,
чтобы цена картины не ходила за биржей.

### Безопасность — три прохода, отчёт в `SECURITY.md`
Закрыты все 15 пунктов ТЗ. Реализовано: шифрование персональных данных
покупателей AES-256-GCM, хеширование IP в журнале аудита, антифрод-оценка
заказов, rate limiting, проверка Origin на CSRF, валидация загружаемых файлов по
содержимому (magic bytes через sharp), блокировка перебора пароля, журнал
безопасности.

Найдено и исправлено при проверках: открытый редирект на странице входа через
`?callbackUrl`, 500 на произвольном значении фильтра галереи, honeypot-заглушка,
не пропускавшая ветку тихого успеха, `upgrade-insecure-requests` на plain-http,
статика с расширением, уходившая в языковой редирект (из-за неё **вообще не
работал скрипт темы**).

## Чего НЕ делать

1. **Не сочиняй за художника «историю работы».** Поле `story` намеренно пустое:
   это его голос — где писалось, почему, что он там увидел. Описание («что
   изображено») писать можно, историю — нет.
2. **Не переводи тексты машинно между языками.** EN и KO версии пишутся заново.
   Копия русского текста — дубль, за который поисковик режет обе версии.
3. **Не обрезай изображения работ.** Кадр — часть работы. Пробовали квадратные
   поля в сетке: ряды ровнее, но горизонтальный холст становится вдвое мельче
   вертикального, а подпись отрывается пустым полем. Отказались.
4. **Не коммить `.env`.** `.env.example` — коммитится.
5. **Не меняй `slug` у опубликованных работ** — это адрес в индексе поисковика.
6. **Не предлагай 3D-зал и не обновляй Prisma до 7.**

## Открытые вопросы и долги

1. **Деплой не сделан.** Рекомендованная связка: Vercel Pro ($20/мес) + Neon
   (бесплатно) + Cloudflare R2 (бесплатно, не берёт за трафик) + домен
   (~$12/год). Заказчик сомневается насчёт трёх аккаунтов; альтернатива в один
   аккаунт — всё через Vercel Marketplace с хранилищем Vercel Blob, дороже при
   росте трафика. Работа с файлами спрятана за один интерфейс
   (`src/lib/storage.ts`), смена хранилища — работа на полчаса.
2. **Фотографии работ не залиты.** Локальная папка `storage/uploads` годится
   только для разработки: на Vercel файловая система эфемерна. Нужно объектное
   хранилище.
3. **Утёкший токен.** В истории git от прежнего телеграм-бота остался живой
   `BOT_TOKEN` в закоммиченном `.env`. **История не переписывалась** — это
   разрушительная операция, решение за владельцем. Токен нужно отозвать в
   BotFather. Напомни об этом.
4. **Онлайн-оплаты нет.** «Оформить заказ» создаёт заявку, владелец видит её в
   `/admin/orders`. Платёжный шлюз подключается в `src/app/api/orders/route.ts`.
5. **2FA для админки** — поля в схеме есть, TOTP-флоу не реализован.
6. **Коллекции пусты.** На девяти работах делить не имело смысла; на 50+ —
   имеет. Раздел в админке готов.
7. **Галерея без постраничности.** На 50 работах приемлемо (ленивая загрузка
   картинок), на 100+ понадобится.
8. **Naver.** После запуска — регистрация в Naver Search Advisor и корейский
   блог: для внешнего сайта это основной канал попадания в выдачу Naver.

## Команды

```bash
npm run dev          # разработка
npm run build        # прод-сборка
npm run lint         # eslint
npm run db:migrate   # prisma migrate dev
npm run db:deploy    # prisma migrate deploy (прод)
npm run db:seed      # демо-данные + администратор
npm run db:import    # реальный каталог из prisma/catalog.json
                     # -- --refresh-seo пересобирает SEO-заголовки
npm run db:studio    # просмотр базы
```

Переменные окружения — в `.env.example`, там же объяснено назначение каждой.
Критично: при смене `ENCRYPTION_KEY` ранее сохранённые заказы и сообщения
станут нечитаемыми.

## Как работать

- Проверяй результат **в браузере**, а не только сборкой. Два серьёзных бага
  (нерабочий скрипт темы, битые корейские адреса) сборка и линтер пропустили.
- Комментируй в коде **причину** решения, а не пересказ кода.
- Показывай скриншоты после изменений в интерфейсе.
- Коммить по-русски, осмысленными сообщениями, пуш в рабочую ветку.
- Прежде чем предлагать переделку — прочти, почему сделано так: почти у каждого
  неочевидного решения в коде есть комментарий с обоснованием.
